# بستر فنی و کانتکست عمیق پروژه برای ایجنت (CONTEXT.md) 🧠

این مستند، راهنمای فنی عمیقی درباره بخش‌های پیچیده پروژه **HikStatus** ارائه می‌دهد. ایجنت‌های هوشمند موظفند پیش از اعمال هرگونه تغییر در سورس‌کدها، مفاهیم و معماری فنی توصیف شده در این سند را به طور کامل درک نمایند.

## 🔒 ۱. سیستم دسترسی چندگانه و نقش‌های کاربر (RBAC)

پروژه از چهار نقش متمایز کاربری بهره می‌برد:
1. **`admin`:** دسترسی تام بدون فیلتر گروهی.
2. **`it_manager`:** دسترسی مدیریتی و ویرایش اطلاعات محدود به کارخانجات مجاز.
3. **`inspector`:** دسترسی مشاهده پیشرفته و ثبت دلایل قطعی.
4. **`group_view`:** مشاهده‌گر ساده بدون امکان ویرایش.

### فیلد دسترسی چندگانه (`accessible_group_ids`):
برای نقش‌های `it_manager` و `inspector` علاوه بر گروه اصلی کاربر (`group_id`)، یک فیلد متنی تحت عنوان `accessible_group_ids` وجود دارد که لیستی کاما-جدا شده از شناسه‌های کارخانجات مجاز را ذخیره می‌کند (مثال: `1,3,4`).

> [!WARNING]
> **اعتبارسنجی دسترسی به تصاویر زنده و استریم**
>
> در گذشته خطایی منطقی وجود داشت که دسترسی کاربران چندگروهه را در بخش گرفتن Snapshot و استریم زنده ویدئو مسدود می‌کرد. همواره برای بررسی دسترسی کاربر به دوربین/NVR، از تابع کمکی `get_user_accessible_groups(user, session)` استفاده کنید و گروه مربوطه را در لیست آرایه گروه‌های برگشتی ارزیابی نمایید:
> ```python
> accessible_groups = get_user_accessible_groups(user, session)
> if accessible_groups is not None and target_group_id not in accessible_groups:
>     raise HTTPException(status_code=403, detail="دسترسی غیرمجاز")
> ```

## ⚡ ۲. پیشگیری از الگوهای مخرب N+1 Query و پیچیدگی $O(N^2)$

دیتابیس سیستم به عنوان گلوگاه اصلی برنامه عمل می‌کند. بنابراین، بارگذاری تکراری داده‌ها درون حلقه‌ها به شدت ممنوع است.

### الگوی بهینه لود فله‌ای (Batch Prefetching) رویدادهای خاموشی:
در کدهای گزارش‌گیری یا تحلیل پس‌زمینه قطعی‌ها (`task_analyze_outages`)، به جای اجرای کوئری در ازای هر دوربین، تمام رویدادهای هم‌پوشان با بازه کل را ابتدا در یک کوئری مستقل لود کرده و سپس در حافظه به کمک دیکشنری مپ کنید:

```python
from collections import defaultdict

# واکشی فله‌ای تمام رویدادها
events = session.exec(
    select(DowntimeEvent).where(
        DowntimeEvent.start_time < end_dt,
        (DowntimeEvent.end_time == None) | (DowntimeEvent.end_time > start_dt)
    )
).all()

# دسته‌بندی با مپ In-Memory زمان ثابت O(1)
events_by_camera = defaultdict(list)
for e in events:
    events_by_camera[e.camera_id].append(e)
```

## 🔒 ۳. رمزنگاری اطلاعات حساس دستگاه‌های ضبط تصاویر

پسورد دستگاه‌های NVR برای ممانعت از نشت اطلاعات، به صورت متن آشکار (Plain Text) ذخیره نمی‌شود.
* **کلید رمزنگاری:** سیستم با استفاده از ماژول `cryptography` و الگوریتم متقارن **Fernet** اقدام به رمزگذاری کلمات عبور می‌کند.
* **متدهای تبدیل:** توابع `encrypt_password(password)` و `decrypt_password(encrypted_password)` در ماژول `database.py` وظیفه مدیریت این لایه امنیتی را بر عهده دارند. هیچ‌گاه پسورد خام را به طور مستقیم در دیتابیس ثبت نکنید.

## 🔀 ۴. بهینه‌سازی منطق تغییر آی‌پی NVR (Cascade IP Change Transaction)

آدرس IP دستگاه NVR به عنوان کلید اصلی (Primary Key) در پایگاه داده عمل می‌کند. از آنجا که چندین جدول دیگر (نظیر دوربین‌ها و لاگ‌ها) به این کلید وابسته هستند، تغییر IP دستگاه ضبط ملزم به اجرای تراکنش آبشاری (Cascade Transaction) اختصاصی است:
1. سیستم یک دستگاه ضبط جدید با آدرس IP جدید ایجاد می‌کند.
2. تمامی رکوردهای مرتبط در جدول `Camera` و `CameraChangeEvent` را به آدرس IP جدید منتسب می‌نماید.
3. در نهایت، رکورد قدیمی NVR را برای حفظ سلامت ارجاعی دیتابیس به طور کامل حذف می‌سازد.

## 🌐 ۵. دکوراتور اختصاصی نرخ محدودکننده درخواست (@rate_limit)

جهت ایمن‌سازی پنل در برابر حملات بروت‌فورس (Brute-force) یا تکذیب سرویس (DoS)، برخی مسیرها به دکوراتور `@rate_limit` مجهز شده‌اند.

> [!IMPORTANT]
> **ارسال Request به عنوان آرگومان ورودی**
>
> دکوراتور `@rate_limit` برای استخراج صحیح آدرس IP کلاینت نیاز مبرم دارد که اندپوئینت هدف حتماً شیء `request: Request` از کتابخانه FastAPI را به عنوان ورودی دریافت کند. در غیر این صورت، نرخ محدودکننده به یک فیلتر عمومی (Global) بر روی تمام آی‌پی‌ها تبدیل می‌شود که کارکرد کاربران سیستم را دچار اخلال خواهد کرد.

## 🔌 ۶. پارس کردن پیام‌های XML هایک‌ویژن و تابع `_parse_xml`

سامانه برای تعامل با دستگاه‌ها از پیام‌های مبتنی بر وب‌سرویس اختصاصی ISAPI هایک‌ویژن سود می‌برد که به صورت فایل‌های پاسخ XML بازگردانده می‌شوند.
* **چالش تداخل فضای نام (xmlns):** وجود ویژگی `xmlns` در المنت ریشه فایل‌های XML هایک‌ویژن، کوئری زدن بر روی نودها را بسیار دشوار می‌سازد.
* **راهکار پروژه:** از تابع اختصاصی `_parse_xml(content_str)` استفاده کنید. این تابع با کمک عبارات باقاعده (Regex) فضای نام را به صورت زیر حذف و پاک‌سازی می‌کند:
  ```python
  re.sub(r'xmlns="[^"]+"', '', content_str, count=1)
  ```
  با این کار، المنت‌ها به سادگی و بدون نیاز به تعریف نیم‌اسپیس‌ها قابل کوئری هستند.
