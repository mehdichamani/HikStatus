# معماری و ساختار فنی پروژه HikStatus 🏗️

سامانه **HikStatus** بر پایه معماری ماژولار و مدرن، جهت پایش پایدار و بدون وقفه دوربین‌های مداربسته و دستگاه‌های ضبط تصاویر (NVR) طراحی شده است. در این مستند، ابعاد فنی مختلف پروژه شامل الگوهای طراحی بک‌اند، نحوه سازماندهی فرانت‌اند، ساختار داده‌ها در پایگاه داده SQLite و سیاست‌های کارایی و بهینه‌سازی تبیین می‌گردد.

---

## 💻 ۱. معماری بک‌اند (Backend Architecture)

بک‌اند سامانه با استفاده از فریم‌ورک قدرتمند **FastAPI** و زبان پایتون ۳.۱۲ توسعه یافته است. استفاده از برنامه‌نویسی ناهمگام (Asynchronous) به وب‌سرویس اجازه می‌دهد تا درخواست‌های کاربران را بدون مسدود شدن توسط حلقه‌های طولانی پایش تجهیزات پاسخ دهد.

اجزای اصلی لایه بک‌اند به شرح زیر تقسیم‌بندی می‌شوند:

* **هسته سرور (`main.py`):** شامل پیکربندی اصلی وب‌سرور، مسیرهای API، مکانیزم‌های احراز هویت سشن‌محور، لایه‌های میانی (Middleware) نظیر CORS و اعتبارسنجی نشست‌های کاربری (User Sessions).
* **حلقه مانیتورینگ پس‌زمینه (`monitor.py`):** یک سرویس مستقل و موازی که به صورت دوره‌ای اقدام به Polling دستگاه‌های NVR و استخراج وضعیت آنلاین/آفلاین دوربین‌ها از طریق وب‌سرویس اختصاصی **ISAPI** هایک‌ویژن می‌کند. این ماژول همچنین رویدادهای قطعی و تغییر در کانال‌های ضبط را شناسایی و ثبت می‌نماید.
* **سیستم هشداردهی (`alerts.py`):** وظیفه ارسال هشدارهای قطعی و رفع قطعی را از طریق دو کانال ایمیل (پروتکل SMTP) و تلگرام (Bot API) بر عهده دارد. این بخش به مکانیزم‌های هوشمند جلوگیری از اسپم (Muting و Delay) مجهز است.
* **زمان‌بند کارهای سیستمی (`scheduler.py`):** مدیریت دوره‌ای کارهای تکرارپذیر نظیر پاک‌سازی سشن‌های منقضی شده، بررسی سلامت سخت‌افزاری NVRها (`sync_nvr_health`) و آنالیز دوره‌ای قطعی‌ها.
* **محاسبه‌گر آمار و گزارش‌ها (`camera_stats.py`):** پیاده‌سازی متدهای بهینه جهت استخراج میزان پایداری دوربین‌ها در بازه‌های زمانی مختلف و تولید خروجی‌های آماری.
* **مدیریت نرخ درخواست‌ها (`rate_limiter.py`):** پیاده‌سازی یک دکوراتور اختصاصی تحت عنوان `@rate_limit` که با بررسی هدرهای درخواست کلاینت، دسترسی بیش از حد مجاز به APIهای حساس را مسدود می‌سازد.

## 🎨 ۲. معماری فرانت‌اند (Frontend Architecture)

فرانت‌اند سامانه به صورت یک **برنامه تک‌صفحه‌ای (Single Page Application - SPA)** با استفاده از تکنولوژی‌های اصیل وب (Vanilla HTML5, CSS3, JavaScript) و بدون وابستگی به هیچ فریم‌ورک سنگینی (نظیر React یا Vue) توسعه یافته است که بارگذاری بسیار سریع پنل را تضمین می‌کند.

ویژگی‌های کلیدی بخش کاربری:

* **پشتیبانی کامل از راست‌چین (RTL):** طراحی اختصاصی برای زبان فارسی همراه با استفاده از قلم بومی و زیبای «وزیرمتن» (Vazirmatn) جهت ارتقای تجربه کاربری.
* **پوسته تاریک و روشن (Dynamic Theming):** سامانه از سه وضعیت تم (سیستم / تیره / روشن) پشتیبانی می‌کند. تم کلاینت در عنصر ریشه HTML تحت هدر `data-theme` تنظیم شده و وضعیت ترجیحی کاربر با کلید `hikstatus-theme` در `localStorage` مرورگر ذخیره می‌شود.
* **ارتباط بلادرنگ (WebSockets):** به محض تغییر وضعیت یک دوربین در پس‌زمینه، رویداد به‌روزرسانی از طریق وب‌ساکت به مرورگر کلاینت‌ها ارسال شده و رابط کاربری بدون نیاز به رفرش صفحه به‌روز می‌شود.
* **نقشه تعاملی و کلاسترینگ:** با بهره‌گیری از کتابخانه **Leaflet** و پلاگین کلاسترینگ مارکرها (`Leaflet.markercluster`)، دوربین‌ها به صورت کلاستر شده روی نقشه‌های جغرافیایی یا پلان‌های تصویری اختصاصی (مانند طبقات کارخانه) نشان داده می‌شوند.

## 💾 ۳. ساختار پایگاه داده (Database Schema)

سامانه از پایگاه داده محبوب و پرسرعت **SQLite** در مسیر `data/monitor.db` استفاده می‌کند. جهت بهبود همزمانی خواندن و نوشتن، پایگاه داده در حالت **WAL (Write-Ahead Logging)** پیکربندی شده است.

مدل‌های داده با استفاده از کتابخانه **SQLModel** (ترکیبی کارآمد از SQLAlchemy و Pydantic) توسعه یافته‌اند. این مدل‌ها به شرح زیر مپ می‌شوند:

```
┌─────────────────┐       ┌───────────────┐       ┌────────────────────┐
│    NVRGroup     │◄──────┤      NVR      │◄──────┤       Camera       │
│  (گروه‌های NVR)  │       │ (دستگاه ضبط)  │       │  (دوربین‌های مداربسته)│
└────────┬────────┘       └───────────────┘       └─────────┬──────────┘
         │                                                  │
         │                                                  ▼
         │                                        ┌────────────────────┐
         │                                        │   DowntimeEvent    │
         │                                        │   (رویدادهای قطعی)  │
         │                                        └─────────┬──────────┘
         │                                                  │
         ▼                                                  ▼
┌─────────────────┐                               ┌────────────────────┐
│       Log       │                               │ OutageExplanation  │
│(لاگ‌های سیستمی) │                               │  (رفع ابهام قطعی)  │
└─────────────────┘                               └────────────────────┘
```

### جداول اصلی پایگاه داده:

1. **User (کاربران):** اطلاعات کاربران شامل هش پسورد (PBKDF2-HMAC) و سکرت‌های تولید کد دو مرحله‌ای (2FA).
2. **NVRGroup (گروه‌های کاری):** تقسیم‌بندی دسترسی دوربین‌ها و تنظیمات نقشه کلاینت بر اساس مجموعه‌ها یا شعبات کارخانجات.
3. **NVR (دستگاه‌های ضبط):** ذخیره‌سازی اطلاعات اتصال و آدرس‌های IP و پورت‌های RTSP دستگاه‌های هایک‌ویژن.
4. **Camera (دوربین‌ها):** ذخیره مشخصات کانال‌ها، درجه اهمیت (بحرانی/معمولی/کم)، مختصات نقشه و اطلاعات مخروط دید (FOV).
5. **DowntimeEvent (رویدادهای قطعی):** ثبت دقیق بازه زمانی ابتدا و انتهای هر قطعی رخ داده برای دوربین‌ها.
6. **OutageExplanation (توضیحات قطعی):** سیستم رفع ابهام قطعی‌ها جهت ذخیره علت و جزئیات قطعی‌ها توسط ناظران شبکه.
7. **OutageCause (علل قطعی):** لیست مقادیر مجاز و پیش‌تعریف شده دلایل خاموشی دوربین‌ها.
8. **Settings (تنظیمات):** ذخیره جفت‌های کلید-مقدار تنظیمات سراسری سیستم (نظیر SMTP، تلگرام و پارامترهای تحلیل قطعی).

## ⚡ ۴. اصول کارایی و جلوگیری از گلوگاه‌ها

جهت ارتقای پایداری سامانه در محیط‌های بزرگ کارخانه‌ای، اصول مهندسی زیر در کدهای پروژه لحاظ شده است:

* **حذف خطای N+1 Query:** در تمام توابع گزارش‌گیری و تحلیل‌های دوره‌ای قطعی‌ها، از اجرای کوئری‌های تکراری درون حلقه‌ها جلوگیری شده است. در عوض، داده‌ها با کوئری‌های فله‌ای (Batch Query) لود شده و در قالب یک دیکشنری در حافظه موقت تجمیع و پردازش می‌شوند ($O(1)$ lookup).
* **کاهش پردازش CPU برای استریم زنده:** به دلیل بار پردازشی سنگین ناشی از دیکد و انکود تصاویر RTSP توسط `ffmpeg` در سمت سرور، محدودیت‌های سراسری پخش همزمان به صورت پیش‌فرض بر روی حداکثر ۳ اتصال سراسری تنظیم شده است.
* **دسترسی کارآمد در لایه امنیتی (RBAC):** نقش‌های کاربری (`admin`، `it_manager`، `inspector` و `group_view`) به صورت بهینه هم در لایه API و هم در رابط کاربری کنترل می‌شوند. فیلد دسترسی‌های چندگانه (`accessible_group_ids`) به کاربران IT اجازه می‌دهد بدون افت سرعت، به چند کارخانه مشخص دسترسی همزمان داشته باشند.
